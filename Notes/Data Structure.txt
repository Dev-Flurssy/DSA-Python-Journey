DATA MANIPULATION

Data Manipulation refers to storing, retrieving, processing, and transforming data so that it can be used effectively by computers and users.

------------------------------------------------------------
DATA MANIPULATION IN THE REAL WORLD

Data Manipulation involves:
1. User Data Storage Representation: User data must be stored in a format that a computer can understand and process.

Example:
Name = "Bisola"
Age = 20

-----------------------------------
2. Data Retrieval: Data stored in a computer should be retrieved and presented in a form that users can understand.

Example:
Displaying a student's grade from a database.

-----------------------------------

3. Data Transformation: Data often needs to be converted from one form to another.

Examples:
Text to Numbers
Celsius to Fahrenheit
Raw Data to Reports

------------------------------------------------------------
DATA REPRESENTATION

Data is represented by data values that are: Temporarily stored in a program's memory or Permanently stored in a file

Examples:
Variables
Arrays
Files
Databases

------------------------------------------------------------
DATA STRUCTURE

A Data Structure is a structured collection of data.
Programs follow specific rules to access and process the data efficiently.

Formula: Data Structure = Organization of Data + Operations on Data
Meaning: How data is stored + How data is processed

------------------------------------------------------------
CHOOSING A DATA MODEL

The choice of a data model depends on two important factors.

-----------------------------------
1. Rich Structure: The model should represent real-world relationships accurately.

Example:
Student → Courses
Employee → Department

-----------------------------------
2. Simplicity: The model should be simple enough for fast processing and easy implementation.

Goal:
Represent data accurately
AND
Process data efficiently

------------------------------------------------------------
CLASSIFICATION OF DATA STRUCTURES

Data Structures are classified into:
1. Primitive Data Structures
2. Non-Primitive Data Structures

------------------------------------------------------------
PRIMITIVE DATA STRUCTURES

Machine instructions work directly on primitive data structures.

Examples:
Integer (int)
Float
Character (char)
Boolean (bool)


Characteristics:
Simple
Built into the language
Store individual values
Directly understood by the CPU

------------------------------------------------------------
NON-PRIMITIVE DATA STRUCTURES

Non-Primitive Data Structures are organized collections of data items.

The data may be: 
Homogeneous (same type) 
OR
Heterogeneous (different types)

Examples:
Array
Linked List
Stack
Queue
Tree
Graph
Hash Table


Characteristics:
Store multiple values
More complex
Used to model real-world relationships

------------------------------------------------------------
ABSTRACT DATA TYPE (ADT)

An Abstract Data Type (ADT) defines:
The set of values and the operations performed on those values

An ADT focuses on:
What the data does
Not how it is implemented

-----------------------------------
ADT EXAMPLE
Collection of Numbers

Possible Operations:
Read
Insert
Delete
Sort
Search
Print

------------------------------------------------------------
ALGORITHM

An Algorithm is a technique used by a computer to solve a problem.
Definition: An Algorithm is a finite collection of instructions that performs a specific task.

------------------------------------------------------------
CHARACTERISTICS OF AN ALGORITHM

1. Input: The algorithm must have zero or more inputs.
2. Output: The algorithm must produce at least one output.
3. Definiteness: Every instruction must be clear and unambiguous.
4. Finiteness: The algorithm must terminate after a finite number of steps.

------------------------------------------------------------

How much memory an algorithm uses
How much CPU time an algorithm requires

Purpose:
Compare different algorithms that solve the same problem.

Running a program on test data
Checking whether the results are correct

Repeating the process until correct results are obtained

Evaluating overall performance

Memory that does not depend on inputs or outputs.

Examples:

Characteristics:
Constant memory
Does not change with input size

------------------------------------------------------------
VARIABLE PART

Memory that depends on input size.

Examples:
Arrays
Lists
Recursion Stack
Dynamic Memory Allocation

Characteristics:
Increases as input size increases

------------------------------------------------------------
SPACE COMPLEXITY

Space Complexity measures the amount of memory (RAM) required by an algorithm while it is running.
It helps determine how much memory an algorithm needs to execute.

------------------------------------------------------------
SPACE COMPLEXITY FORMULA

S(p) = C + Sp

Where:
C  = Fixed Part
Sp = Variable Part
Total Space = Fixed Space + Variable Space

------------------------------------------------------------
FIXED PART

The Fixed Part is the memory required regardless of the input size.
This memory does not increase or decrease when the number of inputs changes.

Examples:
result = 0
i = 0

These variables need memory whether the array contains:
5 elements
100 elements
1,000,000 elements

Characteristics:
Constant memory usage
Independent of input size
Always exists during execution

------------------------------------------------------------
VARIABLE PART

The Variable Part depends on the size of the input.
As the input size increases, the memory required also increases.

Example:
a = [7]

Needs less memory than:
a = [7, 2, 15, 9]

Because the second array contains more elements.

Characteristics:
Depends on input size
Grows as data grows
Usually stores arrays, lists, recursion stacks, etc.

------------------------------------------------------------
MAX ALGORITHM

Algorithm MAX
result = a[1]

for i = 2 to n
    if (a[i] > result)
        result = a[i]

return result

------------------------------------------------------------
MEMORY REQUIRED BY MAX

Suppose:
a = [7, 2, 15, 9]
n = 4

The algorithm needs memory for:
Variable n
n = 4

Memory Required:
1 word

------------------------------------------------------------
Variable result
result = 7

Memory Required:
1 word

------------------------------------------------------------
Variable i
i = 1, 2, 3, 4

Memory Required:
1 word

------------------------------------------------------------
Array a
[7, 2, 15, 9]

Contains n elements.
Memory Required:
n words

------------------------------------------------------------
TOTAL SPACE FOR MAX

Array a      = n words
Variable n   = 1 word
Variable i   = 1 word
Variable result = 1 word

Total: S(p) ≥ n + 3

Meaning:
The algorithm requires at least n + 3 words of memory.

------------------------------------------------------------
RECURSIVE ALGORITHM

Algorithm RSum(a,n)
if n <= 0
    return 0
else
    return RSum(a,n-1) + a[n]

------------------------------------------------------------
WHY RECURSION USES MORE MEMORY

Every recursive call creates a new function call.

The system must remember:
1. Current value of n
2. Current value of a[n]
3. Partial sum calculation

These are stored in memory using a structure called the Call Stack.

------------------------------------------------------------
CALL STACK

Suppose:
a = [7, 2, 15, 9]

RSum(a,3)

Recursive Calls:
RSum(a,3)
RSum(a,2)
RSum(a,1)
RSum(a,0)

Each call is stored in memory until the base case is reached.

Stack Representation:
RSum(a,3)
RSum(a,2)
RSum(a,1)
RSum(a,0)

Nothing is removed until RSum(a,0) returns.

------------------------------------------------------------
RECURSION DEPTH

For:RSum(a,3)

The recursive calls are:
3
2
1
0

Total Calls: 4
Which is: n + 1

Therefore:
Depth of Recursion = n + 1

------------------------------------------------------------
MEMORY PER RECURSIVE CALL

Each recursive call stores:
n
a[n]
sum (partial result)

Memory Required:
3 words per call

------------------------------------------------------------
TOTAL SPACE FOR RSUM

Number of Calls: n + 1
Memory Per Call: 3 words
Total Space: S(p) ≥ 3(n + 1)

Meaning:
The recursive algorithm requires at least 3(n + 1) words of memory.

------------------------------------------------------------
ITERATIVE VS RECURSIVE MEMORY USAGE

ITERATIVE MAX

def max_array(a):
    result = a[0]

    for i in range(1, len(a)):
        if a[i] > result:
            result = a[i]

    return result

Memory Used: Array + Few Variables
Space Complexity: O(n)

Reason:
Only the array grows.
Variables remain constant.

------------------------------------------------------------
RECURSIVE SUM

def rsum(a, n):
    if n == 0:
        return a[0]

    return rsum(a, n - 1) + a[n]

Memory Used: Array + Recursion Stack
Space Complexity: O(n)

Reason:
The recursion stack grows with each recursive call.

------------------------------------------------------------
WHY RECURSION REQUIRES MORE MEMORY

Iteration: Reuses the same variables repeatedly.

Example:
result
i

These variables remain the same during execution.

------------------------------------------------------------
Recursion:

Creates a new set of variables for every function call.

Example:
RSum(a,3)
RSum(a,2)
RSum(a,1)
RSum(a,0)

Each call occupies additional memory.
Therefore recursion generally consumes more memory than iteration.

------------------------------------------------------------
FIXED PART

Does not depend on input size.

Examples:
n
i
result

------------------------------------------------------------
VARIABLE PART

Depends on input size.

Examples:
Arrays
Lists
Call Stack

------------------------------------------------------------
MAX ALGORITHM

Memory Required: S(p) ≥ n + 3

Reason:
n words for array
1 word for n
1 word for i
1 word for result

------------------------------------------------------------
RSUM ALGORITHM

Memory Required: S(p) ≥ 3(n + 1)

Reason:
n + 1 recursive calls
3 words per call

------------------------------------------------------------
MEMORY SHORTCUT

Fixed Part → Constant Memory
Variable Part → Grows With Input
MAX → n + 3 words
RSum → 3(n + 1) words
Iteration → Less Memory
Recursion → More Memory
Reason → Recursion Creates a Call Stack

------------------------------------------------------------
COMPLEXITY ANALYSIS

Complexity Analysis measures the time and memory required by an algorithm.
It helps determine how efficient an algorithm is.

------------------------------------------------------------
THREE TYPES OF COMPLEXITY ANALYSIS

1. Best Case
2. Worst Case
3. Average Case

------------------------------------------------------------
BEST CASE

The algorithm gets lucky and performs the minimum number of operations.

Sequential Search Example:
a = [10, 5, 8, 20, 7]
Search for:
10

Steps:
Compare 10 with 10 ✓
Found

Number of Comparisons: 1
Best Case Complexity: O(1)

------------------------------------------------------------
WORST CASE

The algorithm gets unlucky and performs the maximum number of operations.

Sequential Search Example: 
a = [10, 5, 8, 20, 7]
Search for: 7

Steps:
10 ? No
5 ? No
8 ? No
20 ? No
7 ? Yes

Number of Comparisons: 5
Worst Case Complexity: O(n)

------------------------------------------------------------
AVERAGE CASE

The element can occur anywhere with equal probability.

Sequential Search Example:
a = [10, 5, 8, 20, 7]

Position      Comparisons
1st           1
2nd           2
3rd           3
4th           4
5th           5

Average Comparisons:
(1 + 2 + 3 + 4 + 5) / 5
15 / 5
3

Average Comparisons Required: 3

------------------------------------------------------------
AVERAGE CASE FORMULA

Formula: Tave = Σ p(inputi) × steps(inputi)

Where:
p(inputi) = Probability of input i occurring
steps(inputi) = Number of steps for input i

Meaning: Average Time = Probability × Cost + Probability × Cost + ...

------------------------------------------------------------
AVERAGE CASE EXAMPLE

Suppose:
Input A → 50% probability → 2 steps
Input B → 30% probability → 4 steps
Input C → 20% probability → 8 steps

Calculation: 
Tave = 0.5(2) + 0.3(4) + 0.2(8)
= 1 + 1.2 + 1.6
= 3.8

Average Steps: 3.8

------------------------------------------------------------
SEQUENTIAL SEARCH

Sequential Search checks elements one by one until the target is found.

Example:
[ ?, ?, ?, ..., ? ]

The element may be in:
Position 1
Position 2
Position 3
...

Position n
Probability of each position: 1/n

Average Comparisons: (1 + 2 + 3 + ... + n) / n

Using: 1 + 2 + ... + n = n(n + 1)/2

Therefore: [n(n + 1)/2] / n
(n + 1)/2

Average Number of Comparisons: (n + 1)/2

------------------------------------------------------------
SEQUENTIAL SEARCH SUMMARY

Best Case: 1 Comparison
Worst Case: n Comparisons
Average Case: (n + 1)/2 Comparisons
Complexity: O(n)

------------------------------------------------------------
MATRIX ADDITION

Algorithm:

for i = 1 to m
    for j = 1 to n
        c[i,j] = a[i,j] + b[i,j]

Python:

for i in range(m):
    for j in range(n):
        c[i][j] = a[i][j] + b[i][j]

Inner Statement Executes: m × n times
Total Steps: 2mn + 2m + 1
For very large values of m and n: 2mn dominates 2m + 1

Complexity: O(mn)

------------------------------------------------------------
BINARY SEARCH

Binary Search repeatedly divides the search space into half.

Example: [1, 2, 3, 4, 5, 6, 7, 8]
Search for: 5

------------------------------------------------------------
FIRST COMPARISON

Middle Element: 4
Since: 5 > 4

Ignore left half.
Remaining:[5, 6, 7, 8]

------------------------------------------------------------
SECOND COMPARISON

Middle Element: 6
Since: 5 < 6

Keep left half.
Remaining: [5]

------------------------------------------------------------
THIRD COMPARISON

5 Found.
Total Comparisons: 3

------------------------------------------------------------
WHY LOG₂(n)?

Each comparison cuts the data size in half.

Example:
16
↓
8
↓
4
↓
2
↓
1

Number of halvings: log₂(16) = 4
Therefore: Binary Search Complexity = O(log n)

------------------------------------------------------------
BINARY SEARCH SUMMARY

Best Case: 1 Comparison
Worst Case: log₂(n) Comparisons
Average Case: log₂(n) Comparisons
Complexity: O(log n)

------------------------------------------------------------
IMPORTANT EXAM POINTS

Best Case = Minimum number of operations.
Worst Case = Maximum number of operations.
Average Case = Expected number of operations.

Sequential Search:
Best    = 1
Worst   = n
Average = (n + 1)/2
O(n)

Binary Search:
Best    = 1
Worst   = log₂(n)
Average = log₂(n)
O(log n)

Matrix Addition:
Total Steps = 2mn + 2m + 1
Complexity = O(mn)

------------------------------------------------------------
MEMORY SHORTCUT

Sequential Search → Check One-by-One → O(n)
Binary Search → Divide by Two → O(log n)
Matrix Addition → Nested Loops → O(mn)
Best Case → Luckiest Case
Worst Case → Unluckiest Case
Average Case → Expected Case

------------------------------------------------------------
BIG OH NOTATION (O)

Big Oh Notation describes the upper bound (worst-case growth) of an algorithm.
It tells us how fast an algorithm grows when the input size becomes very large.
Big Oh focuses on the maximum amount of work an algorithm may perform.

------------------------------------------------------------
DEFINITION OF BIG OH

A function f(n) is O(g(n)) if there exist positive constants:
c
n₀

such that:
f(n) ≤ c·g(n)
for all:
n > n₀

------------------------------------------------------------
MEANING

f(n) = Actual running time or number of operations
g(n) = Simpler function used to describe growth
c = Constant multiplier
n₀ = Starting point from which the inequality holds

------------------------------------------------------------
BIG OH INTERPRETATION

If:
f(n) ≤ c·g(n)

Then:
f(n) never grows faster than g(n) multiplied by some constant c.

Therefore:
f(n) is O(g(n))

------------------------------------------------------------
GRAPHICAL IDEA

For sufficiently large values of n:
f(n) stays below c·g(n)

Visualization:
c·g(n)
│
│       /
│      /
│     /
│    /
│   /
│  /  f(n)
│ /
│/
└───────────────────► n
        n₀

After n₀:
f(n) ≤ c·g(n)

------------------------------------------------------------
BIG OH RULES

If:
f₁(n) = O(g₁(n))
and
f₂(n) = O(g₂(n))

Then:
Addition Rule:
f₁(n) + f₂(n)
= O(max(g₁(n), g₂(n)))

------------------------------------------------------------
MULTIPLICATION RULE

f₁(n) × f₂(n)
= O(g₁(n) × g₂(n))

------------------------------------------------------------
EXAMPLE 1

Let:
f(n) = 4n + 3

We can write:
4n + 3 ≤ 5n

for all:
n ≥ 3

Therefore:
f(n) = O(n)

Where:
c = 5
n₀ = 3

------------------------------------------------------------
WHY?

For large n:
4n dominates 3
The constant 3 becomes insignificant.

Therefore:
4n + 3 behaves like n

So:
O(n)

------------------------------------------------------------
EXAMPLE 2

Let:
f(n) = 9n² + 5n + 3

For:
n ≥ 6

We have:
9n² + 5n + 3 ≤ 10n²

Therefore:
f(n) = O(n²)

Where:
c = 10
n₀ = 6

------------------------------------------------------------
WHY?

As n becomes large:
n² grows much faster than:
n
constant values

Therefore:
9n² dominates the entire expression.
So:
9n² + 5n + 3
behaves like:
n²

Therefore:
O(n²)

------------------------------------------------------------
THEOREM

If:
f(n) = aₘnᵐ + aₘ₋₁nᵐ⁻¹ + ... + a₁n + a₀

Then:
f(n) = O(nᵐ)

------------------------------------------------------------
IMPORTANT IDEA

For a polynomial:
The highest power term determines the complexity.

Ignore:
Lower powers
Constants
Coefficients

------------------------------------------------------------
EXAMPLES

f(n) = 5n³ + 2n² + 7n + 1
Highest Power:
n³

Therefore:
O(n³)

------------------------------------------------------------
f(n) = 8n⁴ + 3n² + 100

Highest Power:
n⁴

Therefore:
O(n⁴)

------------------------------------------------------------
f(n) = 7n + 50

Highest Power:
n

Therefore:
O(n)

------------------------------------------------------------
f(n) = 3

Constant Function

Therefore:
O(1)

SHORTCUTS FOR FINDING BIG OH

1. Remove Constants
5n → O(n)
100n² → O(n²)

2. Keep Highest Power
n³ + n² + n
↓
O(n³)

3. Ignore Smaller Terms
n² + n + 1
↓
O(n²)
